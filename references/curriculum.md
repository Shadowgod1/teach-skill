# Учебный план серии

План — это ответ на вопрос «в каком порядке и какими порциями учить человека этому продукту». Он строится из карты страниц и функций (шаг 1), а не из структуры кода.

## Единица урока

Один урок — одна цель пользователя, которую можно назвать глаголом: «Создаём первый проект», «Приглашаем коллег», «Настраиваем уведомления».

Чтобы нарезать уроки:

1. Выпиши все функции с числом шагов (действий пользователя) и страницами, на которых они живут.
2. **Большая функция** (6+ шагов, несколько экранов или своя подстраница с вкладками) получает свой урок. Если в ней 15+ шагов или несколько независимых сценариев, дели её на 2–3 урока по сценариям («Создаём счёт», «Отправляем счёт клиенту»).
3. **Мелкие функции** (1–3 шага) объединяются в один урок, если они живут на одной странице или служат одной цели: «Профиль: фото, имя и язык интерфейса». Не больше 4–5 мелких функций в одном уроке.
4. **Страница как урок.** Если страница — самостоятельное место с понятной целью («Отчёты», «Настройки»), урок можно построить по ней: обзор страницы, потом её функции по порядку. Большие подстраницы при этом выделяются в отдельные уроки.
5. **Вводный урок (00).** Если в продукте больше 4 уроков, первым идёт короткий обзор на 45–90 секунд: что это, для кого, где что находится. Это экскурсия по главным экранам без глубоких действий.

## Длина

Длину задаёт содержание, но есть ориентиры:

| Урок | Шагов на экране | Длина |
|---|---|---|
| Обзор / мелкие функции | 3–6 | 0:45–1:30 |
| Одна функция средней сложности | 4–8 | 1:00–2:30 |
| Большая функция | 8–15 | 2:30–5:00 |

Больше 5 минут — сигнал делить урок. Меньше 40 секунд — сигнал объединять с соседним. Оценка: реплики читаются со скоростью около 2,6 слова в секунду, плюс 1–1,5 с на каждое видимое действие.

## Порядок

По пути пользователя: вход и первый запуск → основное действие продукта → работа с результатом → совместная работа → настройки → продвинутое и админка. Урок не опирается на то, что показано позже. Если урок требует данных или настроек из другого урока, укажи это в «нужно знать».

## Аудитория

- `user`: только интерфейс. Код не показывается.
- `dev`: те же уроки плюс сцена «как это устроено» с кодом ключевого обработчика или компонента. Можно добавить отдельные уроки про архитектуру, API и запуск проекта.

## Формат файлов

`curriculum.md` — для человека:

```markdown
# Серия: <Продукт> — обучение
Аудитория: пользователи · Голос: Дмитрий · Уроков: 6 · Общая длина ≈ 11 мин

| № | Урок | Что внутри | Страницы | ≈ Длина | Статус |
|---|---|---|---|---|---|
| 00 | Знакомство с <Продуктом> | экскурсия: задачи, календарь, настройки | /, /calendar, /settings | 1:00 | план |
| 01 | Добавляем и закрываем задачи | новая задача, отметка «готово», фильтр | /tasks | 1:20 | снят 1:18 |
| 02 | Сроки и напоминания | дата, время, повтор, уведомление | /tasks/:id | 2:10 | план |
```

Под таблицей — по абзацу на урок: цель, шаги, что нужно знать заранее, какие данные нужны в кадре.

`curriculum.json` — для повторных запусков:

```json
{
  "series": "Дела — обучение",
  "audience": "user",
  "voice": "dmitri",
  "theme": { "accent": "#ff6b3d" },
  "run": { "start": "npm run dev", "url": "http://localhost:5173", "login": "seed: demo@example.com" },
  "episodes": [
    { "n": 1, "slug": "01-dobavlenie-zadach", "title": "Добавляем и закрываем задачи",
      "goal": "добавить задачу, отметить готовой, отфильтровать готовые",
      "features": ["create-task", "toggle-done", "filter"], "pages": ["/tasks"],
      "estimate": 80, "status": "planned" }
  ]
}
```

`series`, `voice` и `theme` из этого файла используются в каждом уроке, чтобы серия выглядела единым целым.
